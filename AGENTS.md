# Agent guidance

- Use strict TypeScript. Keep domain and application data immutable by default; accept external data as `unknown` and validate it at boundaries.
- Use Effect for asynchronous application operations and typed, expected failures. Catch and classify vendor errors in infrastructure adapters; keep domain and application logic framework- and vendor-independent.
- Do not use exceptions (`throw` or exception-driven control flow) for expected failures. Avoid `any`, `@ts-ignore`, `@ts-nocheck`, `@ts-expect-error`, and inline ESLint suppression comments. Fix the underlying issue or document a narrowly scoped exception in configuration.
- Keep UI, framework, database, and provider dependencies out of domain packages. Put platform-specific behavior behind adapters and compose those adapters at app boundaries.
- Keep authored source files at or below 400 physical lines and eight indentation levels. Extract focused modules instead of compressing code or bypassing the limits. Run `pnpm check:source-limits` to check them; the report separates indentation and line-count violations and sorts each section from highest to lowest.
- Strongly prefer keeping business logic and workflow logic outside React components, in their own files. Pass all dependencies explicitly through parameters rather than importing concrete services or reading hidden global state. Keep React components focused on rendering and interaction wiring; use focused hooks for React state and lifecycle behavior, and delegate logic to those independent modules.
- Group related files by feature and workflow. Add focused subfolders rather than extending large flat directories with filename prefixes; follow `docs/source-layout.md`. Keep package entry points stable when reorganizing internals.
- Avoid duplicating code. Extract repeated UI patterns into reusable components that receive their varying data through props, and extract shared stateful behavior, effects, and interaction workflows into focused custom hooks. Prefer composition with focused child components over large prop lists or forwarding entire state objects through intermediate views. Reuse existing components and hooks before adding new ones; keep pure business logic in independent modules rather than coupling it to React hooks.
- Web and Electron UI must use the existing shadcn primitives and shared components for all supported controls, including selects, dropdown menus, dialogs, accordions and collapsibles. Do not substitute native HTML controls or one-off disclosure buttons when a shared shadcn component exists. Use the established styled wrappers, including visible expand/collapse indicators, keyboard focus and disabled states. Add missing shadcn primitives to the shared UI package rather than implementing local variants. React Native must use the project’s shared native primitives and established interaction patterns.
- Keep scheduling deterministic and pure. Preserve review history as append-only data; treat derived scheduling state as rebuildable.
- Treat imported content and user-authored AI instructions as untrusted. AI output is a proposal until application code validates it and the user approves it.
- Use Prettier for formatting and ESLint for code-quality checks. Keep changes focused and update the README when setup or user-facing behavior changes.

## Named quality commands and artifacts

Shared publication clients validate document hashes and publication acknowledgements against submitted content using the server's canonical protocol. Paired attachment/workspace commits use browser/Electron or native exclusive coordination; uncoordinated media failures retain assets for retry. These source changes do not establish runtime concurrency or live publication acceptance.

Shared tag input and authoring operations preserve unchanged canonical imported tags, including literal delimiters and values beyond authoring limits. Web/Electron and native editors use the same codec. Web card saves now use the existing shared authoring baseline and serialized save lane, with paired attachment persistence and retained drafts on conflict/failure. Full-screen imported-tag and stale-card mock stories cover these UI states; runtime concurrency and browser captures remain unverified.

Web area-settings and review-retention forms also use shared authoring baselines and the existing durable commit lane. Their drafts remain mounted across sync changes, typed failures keep edits available, and reloading latest values requires confirmation. Full-screen conflict/storage-failure mocks render without live providers. Source inspection confirms that shared settings operations preserve schedules, review history and retained deletion evidence; runtime acceptance remains open.

Web area creation/renaming and area/card deletion now use the same durable authoring lane. Creating an area keeps its identity across retries; renaming/deleting captures a content baseline. Failed deletion retains visible content and a retry/cancel request, with fresh confirmation required after a conflicting revision. Full-screen mocks cover rename and deletion recovery. This completes the bounded P0/P1 source inventory, while the operational and verification gates above remain unproven.

Application completion follow-up repairs optimistic import acceptance: JSON, CSV/TSV, Knowledge Area ZIP, Anki and private-backup imports publish UI success after durable workspace/media persistence and retain exact imported content/history/assets for retry. Native adds CSV/TSV parity and a five-tab shell with preserved drafts, scrollable forms and shared area selection. Desktop opens validated shared-area links externally and permits clipboard writes only from its trusted dashboard. Five full-screen native shell stories are registered; scoped client typechecks pass, while browser/device/live-service and release acceptance remain deferred.

Native card authoring also stages verified image/audio attachments before a paired card/media save, preserves drafts after failure and rejects stale picker callbacks. Native imports no longer report success through a media-only temporary fallback when workspace persistence is read-only. The native card-attachment story is registered for full-screen capture; runtime acceptance remains deferred.

## Current local build evidence

The current web production bundle, Electron main/preload/renderer and Expo Android/iOS exports compile successfully with `pnpm build:all` (three uncached tasks). Storybook builds 214 stories; all 181 registered screenshot targets resolve against its generated index. No browser, database or cloud-service operation was run. Compilation and catalog membership do not establish runtime/device acceptance; those gates remain open.

The existing pure suite also passes against current source: 145 tests, zero failures or skipped cases. It covers the shared behaviors represented by its fixtures; it does not close live browser/native, Supabase, OAuth or release acceptance gates.
